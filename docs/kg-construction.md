# Building the knowledge graph (Phase 4, RQ2)

This page details the knowledge-graph construction reported in Section 5.3 of the paper and in its table of KG construction by extraction task. Sources: [`rejection-report.json`](../generated/validated/rejection-report.json), [`validated-kg.xmi`](../generated/validated/validated-kg.xmi) and [E0](experiments.md#e0--context-of-the-evaluation).

Five abstracts are processed by both PubMed tasks (their rejections are counted under guidelines), so 438 document–task pairs cover 433 distinct documents ([datasets.md](datasets.md#the-corpus-433-distinct-documents)).

## Why items were rejected

Every rejected item is annotated with the rule it failed and counted once, under the first rule it failed (some items fail several rules).

| Items | Rule (validation-policy model) | What happened |
|---|---|---|
| 137 relations | `relation_type_and_endpoints_in_schema` | the LLM linked two entity types through a declared relation that the schema does not allow between them |
| 107 relations | `relation_evidence_grounded_in_source` | the quoted evidence does not occur verbatim in the source |
| 35 relations | `relation_endpoints_accepted` | one endpoint had itself been rejected |
| 19 entities | `mention_grounded_in_source` | the quotation does not appear verbatim in the document, usually because the LLM shortened or altered it |
| 2 relations | `relation_confidence_above_threshold` | the LLM's confidence was below the threshold of 0.7 |

Grounding must be checked, not assumed: the character offsets returned by the LLM were wrong for 5,055 of the 5,070 items (99.7%), whose quotations had to be searched for in the source.

## From accepted items to the graph

The loader generated by T5 merges all mentions of an entity into one node, which keeps a provenance link to each of them, and merges relations extracted twice from the same sentence (because document chunks overlap) into one relationship. The 3,539 accepted mentions become 1,346 distinct entities, and the 1,231 accepted relations contain 8 exact duplicates, hence 1,223 distinct relations.

Provenance adds 369 `SourceDocument` nodes, 5 `ExtractionRun` nodes and 4,993 provenance links: 3,510 `EXTRACTED_FROM` links (entity → source document, with the character span) and 1,483 `PRODUCED_BY` links (entity → extraction run). The extraction runs record, for example, which of the two LLM versions used (`gemini-3.5-flash-lite`, and `gemini-3.1-flash-lite` for part of the literature task) produced each fact. Relations carry their provenance as properties of the relationship.
